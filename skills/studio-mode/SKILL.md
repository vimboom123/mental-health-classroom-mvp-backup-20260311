# studio-mode

## 什么时候用

当任务满足任一条件时，默认进入工作室模式：
- 用户明确说“工作室模式”
- 需要多 AI / 多 reviewer 协作
- 任务是中大型项目，而不是一句话小修
- 需要开工报备、阶段汇报、风险上报、结项评分
- 需要 Notion 项目底座 + 本地实时进度双轨跟踪

## 核心原则

工作室模式不是口头叫法，而是一套必须执行的流程：
1. 主动推进
2. 主动汇报
3. 主动判断
4. 主动留痕
5. 主动纠偏

不要停留在“用户问什么才答什么”。

## 启动 SOP（必须执行）

### Step 1: 先发开工状态

开工消息至少包含：
- 已启动
- 任务目标
- 参与 AI 与分工
- 交付标准
- 预计下一次汇报时间

### Step 2: 同步启动 Notion 流程

只要进入工作室模式，就必须在 Notion 项目总表中创建或更新项目底座。

至少写明：
- 项目名
- 目标
- 当前阶段
- 参与角色 / 分工
- 当前阻塞
- 下一步

本机当前项目底座读取脚本：
```bash
scripts/notion_project_snapshot.sh <project-name>
```

当前工作室项目总表 data source id：
- `478ee9d7-d1db-4dc7-85d8-7663db95d6ca`

### Step 3: 真拆工，不要只报分工

默认角色：
- Codex：结构 / 实现 / 骨架 / 方法与一致性
- Gemini：表达 / 呈现 / 文风 / 前端层
- Claude Code：审稿 / 逻辑复核 / 风格统一
- Qwen：中文表达 / 中文润色 / 本土化判断 / 中文 reviewer
- Oracle：全局复盘 / 第二视角 / 收口判断
- 主智能体：PM / 验收 / 统稿 / 汇报

注意：
- 中文任务默认把 Qwen 纳入
- 不能只说角色名字，必须尽快把任务真正拆给对应 AI

### Step 4: 建立实时进度痕迹

工作室项目统一按“双轨状态”运行：
- Notion：项目底座
- 本地状态文件 / 日志 / 文件变更：实时进度痕迹

后台 AI 一旦开工，至少要留下一个可采样痕迹：
- 更新状态文件
- 产出日志 / 文件
- 提交结果
- 同步 Notion

不能只在脑内推进。

建议本地状态路径：
- `studio/status/<project-slug>.md`
- 或按角色拆分：
  - `studio/status/codex.md`
  - `studio/status/gemini.md`
  - `studio/status/qwen.md`
  - `studio/status/oracle.md`

## 定时汇报规则

### 汇报内容结构
默认用：
- 已完成
- 进行中
- 阻塞与风险
- 下一步

### 新闻规则
- 只有早上 8:00 的定时汇报带新闻版
- 12:00 / 20:00 默认不带新闻
- 除非用户临时单独要求，否则其他时段不补新闻

### 汇报生成逻辑
定时汇报必须：
1. 先读 Notion 项目底座
2. 再做实时采样（本地状态文件、git/file changes、任务日志、最新产物）
3. 最后合成汇报

不能跳过 Notion，也不能只复述 Notion。

### 带时间点承诺的提醒机制
凡是“10分钟后汇报”“半小时后提醒”“到点通知”等明确时间点承诺，默认必须挂真实触发机制。

在当前 OpenClaw 环境里，优先方案是：
```bash
openclaw cron add --session isolated --announce ...
```

禁止再用：
- 本地 `sleep`
- 后台 stdout 打印
- 进程日志假装提醒

正式依赖前，最好先做一次短间隔验证（如 1 分钟）。

## 结项 SOP

项目结束后必须做：
1. 验收结论
2. 角色评分（5 分制）
3. 评分记录写入单独评分表
4. 复盘：本次分工哪里有效，哪里失效

## 执行检查清单

每次进入工作室模式，开工前快速确认：
- [ ] 已发开工状态
- [ ] 已创建/更新 Notion 项目底座
- [ ] 已完成真实拆工
- [ ] 已建立实时进度痕迹
- [ ] 已设置下次汇报时间
- [ ] 如果承诺了到点汇报，已挂真实 cron 提醒

如果有任一项没做，不算真正进入工作室模式。
