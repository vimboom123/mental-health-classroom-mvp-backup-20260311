# 网站最小可用实现清单（V1）

项目名：数智赋能示范课堂｜大学生心理健康教育网站

## 一、这一轮目标
把前面已经铺开的产品方案、内容框架、助教规则和风险逻辑，收口成一版真正面向实现的 MVP 清单。

原则：
- 第一版不追求复杂
- 第一版不追求炫技
- 先把能用、能跑、能演示、能继续迭代的最小闭环做出来

---

## 二、第一版最小目标

第一版只要求跑通这条主链：

```text
进入网站
→ 进入模块
→ 看懂一个主题
→ 问助教
→ 做一个练习
→ 风险时能正确分流
```

只要这条主链顺了，第一版就成立。

---

## 三、MVP 页面清单

### 必做页面（P0）
1. 首页
2. 模块总览页
3. 模块详情页 × 3
   - 人际交往
   - 学习心理
   - 情绪调节
4. 助教页
5. 风险帮助页
6. 情景模拟页 × 1~2

### 可以后补（P1 / P2）
- 独立资源中心页
- 更完整的模块扩展页
- 教师端 / 后台管理页
- 更复杂的账号体系

---

## 四、MVP 核心功能清单

### 1. 内容浏览
- 能从首页进入模块总览页
- 能从模块总览页进入 3 个首批模块详情页
- 模块页能显示简介、问题、方法、练习入口

### 2. 助教对话
- 助教页能正常发消息 / 收消息
- 助教直接调用千问 API
- 能返回文本答复
- 能根据问题推荐模块 / 练习

### 3. 风险分流
- 助教能输出 low / medium / high 三档前端状态
- 中风险时前端能上浮风险帮助入口
- 高风险时前端能切到安全优先模式
- 能跳转到风险帮助页

### 4. 练习入口
- 至少 1~2 个情景模拟页可进入
- 模块页能跳转到练习页
- 助教页能推荐练习页

### 5. 基础页面联动
- 首页能跳模块页 / 助教页 / 风险帮助页
- 模块页能跳助教页 / 练习页
- 助教页能跳模块页 / 风险帮助页
- 风险帮助页能返回首页 / 助教页

---

## 五、MVP 不做的东西

第一版先不做这些：
- 复杂用户登录体系
- 用户长期记忆
- 聊天历史云端同步
- 多角色助教
- 复杂动画角色系统
- 重型 3D 数字人
- 复杂教师管理后台
- 自动化数据分析看板
- 太多内容模块一次性铺满

这些都不是第一版成立的必要条件。

---

## 六、助教功能最小范围

### 第一版只做这四件事
1. 识别用户问题更接近哪个模块
2. 给简短、自然、可执行的回答
3. 推荐一个模块 / 练习 / 方法卡
4. 风险时正确分流到风险帮助页

### 第一版不追求
- 泛聊天很强
- 长程任务型陪伴
- 复杂人格扮演
- 多轮深度咨询体验

助教第一版的标准不是“像人”，而是“稳、清楚、边界正确”。

---

## 七、前端最小实现要求

### 页面层
- 每页能正常打开
- 页面跳转关系通
- 响应式基本可用（桌面 / 手机都不崩）

### 组件层
- 导航
- 标题区
- 模块卡片
- 助教聊天区
- 风险帮助条
- 推荐动作区

### 状态层
- 支持 `low / medium / high`
- 能根据风险等级切换页面组件显隐
- 不要求一开始就做很复杂的状态机

---

## 八、后端 / 接口最小实现要求

### 千问接口
- 能发请求
- 能收回复
- 能返回给前端显示

### 风险等级输出
第一版可以先做简单结构返回，例如：

```json
{
  "reply": "...",
  "riskLevel": "medium",
  "recommendedActions": ["open_risk_help", "contact_real_support"]
}
```

也就是说，不一定一开始就做复杂 orchestration，只要能把：
- 回复文本
- 风险等级
- 推荐动作

一起返回给前端，就够支撑第一版。

---

## 九、内容最小填充要求

### 三个模块每个至少具备
- 模块简介
- 3~5 个核心认识
- 2~4 个方法
- 1~2 个练习入口
- 2~3 个助教引导问题

### 风险帮助页至少具备
- 现在先做什么
- 联系谁
- 校内支持资源占位
- 校外 / 全国支持资源占位
- 紧急情况提醒

### 助教页至少具备
- 页面说明
- 边界说明
- 4 个快捷问题
- 风险状态下的前端切换

---

## 十、MVP 验收标准

### 产品验收通过，至少满足这些条件
1. 网站能正常打开并完成主要跳转
2. 三个模块详情页有可读内容
3. 助教能正常和千问 API 对话
4. 助教能根据问题推荐模块或练习
5. 风险帮助页能进入
6. 中 / 高风险时前端状态切换正确
7. 至少 1~2 个练习页可访问

### 不要求第一版做到的
- 内容很全
- UI 很精致
- 动画很复杂
- 所有边缘 case 一次性全覆盖

---

## 十一、推荐开发顺序

### 第一步：页面骨架
- 首页
- 模块总览页
- 3 个模块详情页
- 助教页
- 风险帮助页

### 第二步：千问 API 接入
- 前端消息发送
- 后端请求千问
- 返回 reply + riskLevel + recommendedActions

### 第三步：风险前端联动
- low / medium / high 三态
- 风险帮助入口上浮 / 置顶
- 普通模块推荐降级或隐藏

### 第四步：练习页接入
- 接 1~2 个情景模拟页
- 打通模块页与练习页跳转

### 第五步：再考虑优化
- 文案优化
- 页面细节优化
- 更细的测试样本
- 更复杂动画与表现层

---

## 十二、当前阶段结论
前面做的那些方案、文档和规则，不是白铺的。它们现在已经被压缩成这版 MVP 清单。

如果按“先做一个真能用的版本”来推进，下一步最自然的就是：
1. 把这个清单再拆成开发任务表
2. 进入真正的实现拆工

也就是说，从这里开始，项目已经可以从“策划阶段”转入“开发准备阶段”。
