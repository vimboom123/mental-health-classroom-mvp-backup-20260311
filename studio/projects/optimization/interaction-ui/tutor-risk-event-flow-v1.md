# 助教页 / 风险帮助页事件流说明（V1）

项目名：数智赋能示范课堂｜大学生心理健康教育网站

## 一、这一轮目标
这一轮把前面的风险规则、状态配置、页面原型继续往产品逻辑层推进：
明确从“用户输入一句话”开始，到“页面应该怎么切、动作怎么变、风险帮助页怎么联动”为止，整个事件流怎么走。

这份文档重点不是界面样子，而是：
- 系统先做什么判断
- 页面后做什么切换
- 用户接下来看到什么
- 哪些动作优先

---

## 二、总体事件流框架

整体链路可以先理解成：

```text
用户输入
→ 助教模型初步响应
→ 风险等级判断
→ 前端状态切换
→ 推荐动作重排
→ 风险帮助页联动
→ 用户继续操作 / 退出 / 进入支持路径
```

这里最重要的是：
- 风险判断不能停留在模型输出层
- 页面必须接住这个判断结果

---

## 三、基础事件对象建议

前端或中间层至少可以统一成这样的事件结构：

```json
{
  "userInput": "我最近总觉得活着好累",
  "assistantReply": "...",
  "riskLevel": "medium",
  "uiMode": "support",
  "actions": ["open_risk_help", "contact_real_support"],
  "flags": {
    "hideQuickPrompts": false,
    "hideModuleRecommendations": false,
    "promoteRiskHelp": true,
    "promoteRealSupport": true
  }
}
```

这样后面不管是前端、日志还是验收，都更容易统一。

## 四、低风险事件流

### 触发条件
用户表达普通困扰，例如：
- 拖延
- 学习压力
- 室友沟通问题
- 情绪烦躁但未明显失控

### 事件流
```text
用户输入普通困扰
→ 助教识别为 low risk
→ 输出学习型回复
→ 前端进入 learning 模式
→ 推荐模块 / 练习 / 方法卡
→ 用户继续对话或进入模块页
```

### 页面变化
- 助教页保持正常布局
- 快捷问题正常显示
- 模块推荐与练习推荐保持主位
- 风险帮助页仅保留轻提示入口

### 成功标准
- 用户能顺利继续学习路径
- 不被误导进入危机处理模式

---

## 五、中风险事件流

### 触发条件
用户表达明显被压垮、持续影响生活、强烈自我否定，或出现模糊风险表达，例如：
- 我最近快被压垮了
- 我觉得自己特别差
- 活着好累
- 我不想麻烦别人，所以算了

### 事件流
```text
用户输入中风险表达
→ 助教识别为 medium risk
→ 输出更短、更稳的支持型回复
→ 前端切到 support 模式
→ 风险帮助入口上浮
→ 现实支持动作前置
→ 模块 / 练习推荐降级
→ 用户选择：
   A. 进入风险帮助页
   B. 联系现实支持
   C. 继续做一个最小动作
```

### 页面变化
- 聊天区保留
- 风险帮助提示条进入第一屏
- 现实支持动作区进入主位前列
- 快捷问题折叠或弱化
- 模块 / 练习推荐退到后面

### 成功标准
- 风险帮助页与现实支持优先级高于普通模块推荐
- 用户不会被继续拉进纯学习型体验

---

## 六、高风险事件流

### 触发条件
用户出现明确危机表达，或极强的高风险边缘表达，例如：
- 我不想活了
- 我有点想伤害自己
- 我怕自己会做傻事
- 要是我不在了是不是大家都轻松一点

### 事件流
```text
用户输入高风险表达
→ 助教识别为 high risk
→ 助教停止普通学习型对话
→ 输出安全优先回复
→ 前端切到 safety 模式
→ 风险帮助主卡片置顶
→ 现实支持动作区置顶
→ 隐藏模块 / 练习 / 快捷问题
→ 用户选择：
   A. 进入风险帮助页
   B. 联系现实中的人
   C. 查看校内 / 紧急支持资源
```

### 页面变化
- 顶部强提醒出现
- 风险帮助主卡片主位显示
- 现实支持动作主位显示
- 紧急提醒卡显示
- 普通模块和练习推荐隐藏
- 快捷问题隐藏

### 成功标准
- 页面第一屏明确“先保证安全”
- 不再出现普通学习型主流程干扰

---

## 七、风险帮助页联动事件流

### 从助教页进入风险帮助页
```text
用户触发中 / 高风险表达
→ 助教页生成 open_risk_help 动作
→ 用户点击风险帮助入口
→ 页面跳转或展开风险帮助页
→ 风险帮助页展示：
   - 现在先做什么
   - 可以联系谁
   - 校内支持资源
   - 校外 / 全国支持资源
   - 紧急情况提醒
```

### 风险帮助页后的去向
```text
风险帮助页
→ 用户联系现实支持
→ 或返回助教页
→ 或回首页
```

### 设计建议
- 中风险：可展开 / 可跳转
- 高风险：应做到一眼可见，不必要求用户自己慢慢找入口

---

## 八、推荐动作重排逻辑

### low
```text
模块 > 练习 > 方法卡 > 风险帮助
```

### medium
```text
风险帮助 > 现实支持 > 一个最小继续动作 > 模块 / 练习
```

### high
```text
风险帮助 > 现实支持 > 联系可信任的人 > 校内 / 紧急支持
```

这里最重要的是：
- 高风险时不要再把普通模块动作放在前面
- 中风险时不要让练习卡片压过风险帮助入口

---

## 九、异常事件与回退逻辑

### 1. 风险等级不确定
如果系统不确定在 low / medium 之间：
- 默认保守一点，先按 medium 处理
- 页面先上浮风险帮助入口

### 2. 用户拒绝看风险帮助页
如果用户不进入风险帮助页：
- 中风险下仍可保留一个最小继续动作
- 高风险下应继续优先现实支持出口，不重新回到普通学习型主流程

### 3. 用户切回普通提问
如果用户从风险状态回到普通提问：
- 不要立刻解除风险状态
- 至少保留当前轮次的保护性 UI 状态

---

## 十、一个更完整的事件流示意

```text
[用户输入]
   ↓
[模型回复 + 风险判断]
   ↓
[生成 riskLevel / uiMode / actions]
   ↓
[前端根据 riskConfigMap 更新页面]
   ↓
[推荐动作重排]
   ↓
[用户点击：模块 / 练习 / 风险帮助 / 现实支持]
   ↓
[进入对应路径]
```

这一步其实就是把“模型说了什么”变成“产品要怎么动”。
