# 助教风险反馈样式与交互映射（V1）

项目名：数智赋能示范课堂｜大学生心理健康教育网站

## 一、这一轮目标
这一轮把“风险判断”继续往产品实现层推进：
不再只停留在 prompt 和测试样本，而是明确：
- 助教判断出不同风险等级后
- 前端页面应该怎么变
- 哪些动作该出现
- 哪些动作该隐藏
- 风险帮助页怎么联动

这份文档的目标，是把风险等级、助教话术、页面反馈和用户动作统一到一套映射里。

---

## 二、总体原则

### 1. 低风险
- 保持正常学习型体验
- 模块、练习、方法卡优先
- 风险帮助页仅保留轻入口

### 2. 中风险
- 开始弱中带强地提示风险帮助页
- 现实支持资源优先级提高
- 普通模块推荐仍可保留，但降级

### 3. 高风险
- 安全优先
- 风险帮助页前置
- 现实支持动作前置
- 停止普通学习型对话节奏
- 普通模块 / 练习推荐隐藏或降到次要位置

---

## 三、风险等级 → 前端反馈映射

### A. 低风险

#### 助教状态
- avatar_state = `speaking` / `listening`
- 页面保持常规助教态

#### 页面反馈
- 正常聊天区
- 正常快捷问题区
- 正常推荐模块 / 推荐练习区
- 风险帮助入口仅保留页内轻提示

#### 推荐动作优先级
1. 模块推荐
2. 练习推荐
3. 方法卡推荐
4. 风险帮助入口（弱提示）

#### 页面文案风格
- 平稳
- 学习型
- 可执行导向

---

### B. 中风险

#### 助教状态
- avatar_state = `risk-alert-soft`
- 助教视觉不需要惊吓式变化，但应明显收敛

#### 页面反馈
- 聊天区保留
- 快捷问题区弱化
- 推荐模块区仍可显示，但不抢主位
- 页面顶部或聊天区下方出现 **风险帮助提示条**
- 现实支持入口出现在推荐动作前列

#### 推荐动作优先级
1. 风险帮助页入口
2. 现实支持资源入口
3. 一个最小继续动作（如“只处理眼前最急的一件事”）
4. 模块推荐（降级）

#### 页面文案风格
- 更短
- 更稳
- 减少抽象分析

#### 不该出现的情况
- 大块普通模块推荐还放在主视觉位
- 热门练习区继续强推
- 助教继续长篇解释概念

---

### C. 高风险

#### 助教状态
- avatar_state = `risk-alert`
- 助教进入安全优先状态

#### 页面反馈
- 聊天区保留，但进入“安全分流模式”
- 快捷问题区隐藏
- 普通模块推荐隐藏
- 普通练习推荐隐藏
- 风险帮助页入口 / 现实支持入口置顶
- 可出现强调卡片：
  - 现在先联系谁
  - 先不要一个人待着
  - 先离开危险环境

#### 推荐动作优先级
1. 风险帮助页（强提示 / 置顶）
2. 现实支持资源入口
3. 联系身边可信任的人
4. 校内支持资源

#### 页面文案风格
- 短句
- 直接
- 不煽情
- 不拖延到普通教学节奏

#### 不该出现的情况
- 普通模块卡片还在主位
- 练习按钮仍然明显可点击
- 继续做“课程陪练”风格互动

---

## 四、助教页组件联动建议

### 1. `TutorAvatarPanel`
根据风险等级切换状态：
- low → `idle / speaking`
- medium → `risk-alert-soft`
- high → `risk-alert`

### 2. `QuickPromptChips`
- low：显示
- medium：弱化或折叠
- high：隐藏

### 3. `RecommendedActionPanel`
- low：模块 / 练习 / 方法卡优先
- medium：风险帮助与现实支持置前
- high：只保留风险帮助与现实支持主动作

### 4. `RiskHelpBanner`
- low：弱提示
- medium：明显提示
- high：强提示 + 置顶

## 五、页面元素显隐规则（V1）

### 低风险
- 显示模块推荐
- 显示练习推荐
- 显示快捷问题
- 风险帮助页入口保留轻提示

### 中风险
- 模块推荐保留但降级
- 练习推荐弱化
- 快捷问题弱化
- 风险帮助条上浮
- 现实支持入口前置

### 高风险
- 隐藏模块推荐主区
- 隐藏练习推荐主区
- 隐藏快捷问题
- 置顶风险帮助卡片
- 置顶现实支持动作

---

## 六、风险帮助页联动规则

### 中风险触发
- 页面出现风险帮助入口条
- 用户可选择进入
- 助教回复中要明确建议现实支持

### 高风险触发
- 风险帮助页入口进入强提示态
- 推荐动作只保留安全优先相关项
- 页面不再继续主打学习型内容

### 交互要求
- 不一定强制跳转整页
- 但必须做到：用户一眼能看到安全出口

---

## 七、一个更实际的前端判断逻辑

可以先按这个简单状态机做：

```text
risk_level = low | medium | high

if low:
  show(normal_tutor_ui)
  prioritize(module, practice, resource)

if medium:
  show(normal_tutor_ui + risk_help_banner)
  prioritize(risk_help, real_support, minimal_next_step)
  downgrade(module, practice)

if high:
  show(safety_mode_ui)
  prioritize(risk_help, real_support, contact_person)
  hide(module, practice, quick_prompts)
```

这版足够支撑第一版实现，不必一开始做很复杂的规则引擎。

---

## 八、对前端和产品的落地建议

### 前端侧
- 风险等级至少驱动 3 类 UI 状态切换
- 不要只在文案上变，组件显隐也要变
- 高风险时页面必须明显“收住”

### 产品侧
- 把“推荐什么”与“隐藏什么”一起定义
- 不能只说要加风险帮助按钮
- 要明确普通内容什么时候退后

### 验收侧
- 不只测文本是否安全
- 还要测页面是否按风险等级真的变了

## 九、当前阶段结论
到这里，助教风险链路已经基本形成闭环：
1. 风险规则
2. 风险示例对话
3. Prompt 验收表
4. 边缘样本库
5. 前端风险反馈映射

下一轮如果继续推进，最自然的是：
- 把前端状态映射转成组件级状态表
- 设计风险帮助页和助教页的联动原型说明
- 继续把页面数据结构精化成更接近实现的字段表
