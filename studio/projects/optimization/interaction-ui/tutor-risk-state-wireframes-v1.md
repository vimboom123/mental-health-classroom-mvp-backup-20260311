# 助教页三种风险态原型说明（V1）

项目名：数智赋能示范课堂｜大学生心理健康教育网站

## 一、这一轮目标
这一轮把前面的风险规则、组件状态表、配置字段继续往原型层推进：
直接描述助教页在三种状态下分别应该长什么样：
- 低风险态（learning）
- 中风险态（support）
- 高风险态（safety）

目的不是出视觉稿，而是让产品、前端、交互在进入设计或开发前，对每一种状态的页面结构与优先级有统一理解。

---

## 二、共同原则

### 1. 三种状态不是只换一句文案
风险等级变化后，页面不只应该“说得不一样”，而应该：
- 结构变
- 动作排序变
- 组件显隐变
- 用户注意力焦点变

### 2. 高风险态不是“普通页 + 红色提醒”
高风险态需要进入真正的安全优先模式：
- 普通模块内容退后
- 风险帮助与现实支持前置
- 页面整体“收住”

### 3. 中风险态不能一刀切成高风险
中风险仍保留部分正常交互，但学习内容不再主导。

---

# 三、低风险态原型说明（learning）

## 1. 页面目标
保持助教页的正常学习型体验：
- 帮用户理解问题
- 推荐模块
- 推荐练习
- 给出一个最小可执行动作

## 2. 页面区块顺序
```text
[页面头部]
[助教角色区 + 边界说明]
[聊天区]
[快捷问题区]
[推荐模块 / 推荐练习区]
[风险帮助轻提示]
```

## 3. 视觉重心
- 助教角色与聊天区是主视觉
- 模块与练习推荐是第二优先级
- 风险帮助页仅做轻提示，不抢主位

## 4. 主要动作
1. 继续提问
2. 去模块页
3. 去练习页
4. 看方法卡

## 5. 页面语气
- 学习型
- 清楚
- 友好但克制

---

# 四、中风险态原型说明（support）

## 1. 页面目标
从普通学习型体验切到“支持优先”状态：
- 助教仍然在
- 聊天仍然保留
- 但现实支持与风险帮助开始前置

## 2. 页面区块顺序
```text
[页面头部]
[风险帮助提示条]
[助教角色区（soft risk 状态）]
[聊天区]
[现实支持动作区]
[折叠后的快捷问题区]
[降级后的模块 / 练习推荐区]
```

## 3. 视觉重心
- 风险帮助提示条进入第一屏
- 现实支持动作区进入主视觉前列
- 模块与练习不消失，但退后

## 4. 主要动作
1. 看风险帮助入口
2. 联系现实支持资源
3. 继续处理一个最紧急的问题
4. 再考虑模块 / 练习

## 5. 页面语气
- 更短
- 更稳
- 减少“教学感”

## 6. 不能出现的设计问题
- 热门练习还占第一屏大位置
- 模块推荐比风险帮助更醒目
- 助教页仍像普通学习页，没有明显风险升级感

---

# 五、高风险态原型说明（safety）

## 1. 页面目标
进入安全优先模式。
此时页面最重要的不是继续讲内容，而是：
- 帮用户尽快看到现实支持出口
- 引导离开危险环境或联系现实中的人
- 停止普通学习型互动节奏

## 2. 页面区块顺序
```text
[顶部强提醒区]
[风险帮助主卡片]
[现实支持动作区]
[紧急情况提醒卡]
[助教聊天区（安全引导模式）]
[次级返回入口]
```

## 3. 视觉重心
- 顶部强提醒区和风险帮助主卡片占主位
- 现实支持动作区紧随其后
- 助教角色弱化娱乐感，保留“在场感”但不抢内容主位
- 模块 / 练习 / 快捷问题全部退场

## 4. 主要动作
1. 看风险帮助页
2. 联系身边可信任的人
3. 联系校内 / 本地支持资源
4. 优先处理现实安全，而不是继续课程互动

## 5. 页面语气
- 短句
- 明确
- 稳
- 不煽情

## 6. 必须避免的设计错误
- 还把“继续练习”按钮留在显眼位置
- 还把快捷问题留在聊天框上方
- 用大量解释性文字取代现实动作
- 让用户不知道接下来具体该点哪里

---

## 六、三种状态对比总表

| 项目 | 低风险态 | 中风险态 | 高风险态 |
|---|---|---|---|
| 页面主目标 | 学习引导 | 支持优先 | 安全优先 |
| 聊天区 | 主位 | 保留 | 保留但仅安全引导 |
| 快捷问题 | 显示 | 折叠/弱化 | 隐藏 |
| 模块推荐 | 主位 | 降级 | 隐藏 |
| 练习推荐 | 主位 | 降级 | 隐藏 |
| 风险帮助入口 | 轻提示 | 第一屏明显提示 | 顶部主卡片 |
| 现实支持动作 | 弱/无 | 前置 | 主位 |
| 紧急提醒 | 无 | 无/折叠 | 显示 |
| 页面语气 | 学习型 | 稳定支持型 | 安全分流型 |

---

## 七、一个更直观的切换逻辑

```text
low:
  页面围绕“继续学 / 继续问 / 做练习”展开

medium:
  页面围绕“先获得支持，再决定是否继续学习”展开

high:
  页面围绕“先保证安全，再谈其他”展开
```

这个原则比记很多组件名字更重要。

---

## 八、落地建议

### 1. 产品侧
设计评审时，不要只看文案，要看第一屏到底在强调什么。

### 2. 前端侧
最好不要把三种状态混在一个模板里硬判断所有组件。可以保留一个公共骨架，但显隐和排序要足够明确。

### 3. 验收侧
后续验收时，至少要看：
- risk level 切换后，第一屏是否真的变化
- 高风险时普通模块是否消失
- 中风险时现实支持是否进入主位
